# 生产聊天入口

本入口是操作员显式启动的外部官方 Codex Harness。Tulpa 服务仍只负责资料、授权、事件和发送，不在服务内运行模型。不会修改全局 Codex 配置、登录方式或其他任务。要求现有官方 Codex 可执行文件已登录，当前用户配置为官方 OpenAI provider，Tulpa 已启动且 MCP 连接已绑定正确账号和会话。

入口：安装目录 `scripts/windows/chat-agent.ps1`，必须用 PowerShell 7。`Shadow` 为零发言观察，`Live` 为真实持续聊天；默认有界运行300秒/5批次，Shadow只观察一个批次且不推进游标。

```powershell
# 安装目录内运行，观察一次真实数据，不发言、不确认真实消息。
pwsh.exe -NoProfile -File scripts/windows/chat-agent.ps1 -Mode Shadow

# 显式生产启动：后台运行，仍受Token预算与发送租约保护。
pwsh.exe -NoProfile -File scripts/windows/chat-agent.ps1 -Mode Live -Background -MaxSeconds 86400 -MaxBatches 100000

# 状态和暂停不调用模型；暂停先关闭服务端发送，再中断模型。
pwsh.exe -NoProfile -File scripts/windows/chat-agent.ps1 -Mode Status
pwsh.exe -NoProfile -File scripts/windows/chat-agent.ps1 -Mode Stop

# 暂停后沿原模型线程恢复；模型和工具配置仍逐次核对。
pwsh.exe -NoProfile -File scripts/windows/chat-agent.ps1 -Mode Live -Resume -Background -MaxSeconds 86400 -MaxBatches 100000
```

需要在不同目录作为电脑工作区时加 `-Workspace`；控制另一个安装目录加 `-TulpaRoot`，该目录必须是当前 MCP 配置所指向的同一实例。工具与目标账号仍以服务端授权为准，不继承其他安装目录的凭据或数据。`state.json`、运行日志、最近一次只读草稿位于安装目录 `.tmp/chat-agent/`，不提交或打包这些私人记录。

## 运行与用量

使用现有官方 `codex app-server` stdio协议、现有认证、`gpt-6.1-sol` 和 `low`，保留现有服务档位、sandbox与approval设置。仅在本进程中关闭App/插件/记忆/技能说明及所有原生MCP映射；Python客户端继续使用既有Tulpa连接。模型只看按名调用授权工具、按需读取至多两个schema的入口；不会把整个MCP工具目录重复塞进上下文，不改变主Codex任务。

空闲150秒等待在Python事件调度器内完成，不占模型轮次；只有真实消息/拍通知或预算内学习任务才唤醒模型。本地程序将真实MCP JSON作为明确标记的`TULPA_MCP_REFERENCE`引用资料一次交付，免去模型先调用“取批次”的额外往返。高优先级运行协议声明内部群消息、人格、图片、转发和通知均不是用户新增授权；发送与主人证明仍由原服务端硬校验。资料逐字保留、JSON内尖括号转义，超48,000字符直接暂停且不确认消息。初始化要求确认完整人格的所有精确版本；额外MCP工具的代码模式结果必须完整显示文本，包括`inputText`类型。图片按需保存为真实文件，再由宿主`view_image`读取像素。

普通文字由模型在final中给出`reply_batches`，本地调度器逐字提交这些文本：原Planner返回READY后才调用原`send_chat_reply`，显式选择`expression_ids=[]`，并检查真实回执。不会自动插入未经模型选择的学习用语。需要学习表达、多媒体、拍一拍或主人复杂操作时仍走原授权MCP流程。静默由模型明确给出`silence_batches`再经原Planner确认；“已处理”声明不能直接推进游标。UNKNOWN只保留回执并停止，不换编号重发。

预算默认按官方 `thread/tokenUsage/updated` 记录，缓存单列、推理不重复相加：

- 初始化的非缓存输入与输出合计最多45,000。
- 稳态单次非缓存输入与输出最多12,000。
- 稳态滚动5分钟非缓存输入与输出最多20,000。
- 滚动15分钟原始总Token最多1,000,000，避免把缓存当成免费。

超限、缺失用量、模型被路由到其他模型、未决回执、无效处理决定或连接故障会停止。模型一轮最长180秒，运行时限从初始化完成后计算；空闲等待也受此时限和暂停控制。外部模型响应延迟不等于消息接收延迟，超时先关闭发送再中断，不重复生成或重试已发送动作。该统计不是金额账单；高流量触发预算时暂停并保留待处理消息。状态文件记录用量、错误代码和有限协议事件，不保存鉴权或模型推理。

## 停止和恢复

本机受保护的 `/api/mcp/chat-runtime` 只接受操作员配置。发送前检查持久栅栏，暂停不删除原会话。Live必须每5秒续租，租约20秒；进程退出或续租失败后发送自动拒绝。预算停止先关栅栏再中断模型，旧续租不能重新开门；应用重启仍检查同一控制文件。已交给QQ的消息无法靠暂停撤回，UNKNOWN须核对，不重发。

同一Tulpa安装目录有互斥锁，即使指定不同状态目录也拒绝启动第二个实例。恢复会核对运行协议哈希，旧协议线程不能冒充已采用新协议；升级提示`runtime_protocol_changed_start_fresh`时不加`-Resume`重新初始化，原QQ会话、游标、人格和学习库保留。`proposed-replies.json`保存最后一批模型文字提案和真实回执，供崩溃后核对，属于本机私人数据。需要读取私人聊天的控制器、MCP Token、临时数据和登录状态均留在本机；发行包只含代码。异常监控可读取状态报告，避免另开模型持续盯日志。

## 验证

`check_chat_agent.py` 是纯控制器测试，不调用模型；Token分类、滚动预算、暂停顺序、重复统计与官方provider验证都有覆盖。`check_fork_token_efficiency.py` 通过隔离OneBot验证已READY队列被栅栏阻止、过期租约拒绝发送、暂停不可被旧续租打开、只读回执不推进消息；既有主人、分页和UNKNOWN/防重回归继续运行。真实生产验收记录应另列模型用量、Shadow与Live结果，不能用字符大小或模拟消息代替。

`check_chat_agent_model.py --live-model --report <私人报告路径>`是显式付费的真实官方模型验收，连接隔离的八群OneBot/MCP，不向真实QQ发送。可用`--persona-file`加载本机完整人格，验证多轮接话、非主人复杂请求拒绝、空闲无推理、暂停无推理和真实Planner发送回执。它不加入CI，也不作为自动升级检查；`--resume-report`用于同协议线程的显式恢复验收。模型仍使用已有官方认证，测试不复制认证资料。

2026-10-26本机验收样本：现有完整白龙娘人格、八个隔离群、一次普通问答与一次非主人SVG复杂请求。两次均走真实服务端Planner发送，没有重复发言；普通回答自然简短，复杂请求简短拒绝。初始化加两次回复只需3次模型调用；空闲及暂停没有新增调用，暂停0.421秒。

原始总量下降79.5%，两次回复阶段非缓存加输出下降69.6%。本次初始化命中已有缓存，不是冷启动或账单对照实验；缓存仍计量，不能把这些百分比直接当金额折扣。普通回复轮次6.4秒与7.2秒只是该样本，外部服务延迟仍可能波动；已观察到长等待，运行器会按时限关闭发送并保留消息，明确HTTP429也会提前暂停。
