# 一键连接 QQ

1. 打开 QQ 并登录，再打开 Tulpa。
2. 在 **OneBot 设置 → 连接 QQ**（或 MCP 的连接 QQ 区域）阅读使用细则与隐私政策，主动勾选自动部署授权。
3. 点击 **一键配置**，等待显示 **QQ 已就绪**。

无需手动下载 SnowLuma、选择文件夹、设置管理密码或填写端口、Token。Tulpa 优先验证随包提供的官方完整运行包；未提供时从官方 GitHub 下载。只有多个 QQ 主进程时需要选择目标；QQ 未登录时在 QQ 完成扫码，配置会继续。

MCP 启用和 QQ 就绪分别显示。部署不会增加任何 Agent 的发送、管理或收藏权限；QQ 尚未就绪时，原有历史查询仍可使用。

## 版本与授权

自动部署固定为 [SnowLuma 2.1.1](https://github.com/SnowLuma/SnowLuma/releases/tag/v2.1.1)，不会每次启动追随 latest。下载地址、GitHub 发布的 SHA256、字节数和协议哈希保存在 `chatlocal/snowluma_manifest.json`。协议或范围改变会要求重新同意。运行包先核验再安全解压，失败时不会执行半成品。

项目负责人已确认取得自动部署与整合分发的书面许可。SnowLuma 仍适用自己的[许可](licenses/SL_LICENSE.txt)、[使用细则](https://github.com/SnowLuma/SnowLuma/blob/v2.1.1/EULA.md)及[隐私政策](https://github.com/SnowLuma/SnowLuma/blob/v2.1.1/PRIVACY.md)，不属于 Tulpa 的 MIT 授权范围。Tulpa 不修改上游源码、跳过协议接口或开启对所有 QQ 进程的自动注入。

本机自动接入使用 2.1.1 进程列表中的账号信息；旧 `probe-login` 接口已不再调用。使用完整包自带的 Node 24.22.1，无需更新系统 Node。Linux 本机运行包也有固定清单；Linux Docker 接入继续使用原先独立核对的 1.14.22 镜像，不会因本次更新而更换容器版本。各平台实际测试范围见[开发验证记录](SNOWLUMA_AUTOMATIC_VALIDATION.md)。

## 已有服务和异常恢复

- 已有独立 SnowLuma：展开 **高级：使用已有 SnowLuma**，勾选使用已有文件夹，输入路径，然后使用同一个配置按钮。支持已核对的 1.14.19–1.14.22、2.0.3、2.1.0 和 2.1.1 节点格式；只核对、导入已有连接，不重置密码或关闭外部实例。
- 发现其他服务已接管 QQ 时，保留外部服务并明确提示；不能同时向同一个 QQ 注入另一套 Hook。可以导入原连接，或自行退出原服务、重开 QQ 后重试。
- 当前在线 QQ 与本机已有来源或 MCP 授权不一致时，接入会停止。请选择原账号，或使用独立 Tulpa 数据目录连接另一个账号；不会替换现有资料或扩张旧连接授权。
- 下载中断：点击 **重试**，尝试续传同一固定文件，完成后重新核对全部 SHA256。损坏缓存隔离后重下，不跳过校验。
- 点击 **取消本次接入**：取消后不会继续下载并偷偷启动；已下载文件保留供后续校验复用。
- 点击 **撤销自动配置授权**：立即停止相关 QQ 工具，关闭仅由本实例启动的 SnowLuma。保留 QQ、其他外部服务、聊天、人物卡、学习库和配置文件。
- 重新打开 Tulpa：沿用已有明确授权、同一账号和受保护凭据。账号变化会停止工具，QQ 进程变化时重新核对；多个进程仍需选择。

已有“本地文件夹托管”或旧版本自动部署的绑定不会被自动换成另一个运行目录，亦不重置其密码。本次验证的是新建 2.1.1 实例及同版本重启接续，尚未实现旧托管实例原地升级。此类安装应保留匹配的程序及运行文件备份，或在独立 Tulpa 中配置新版本；已有独立服务也可走连接导入。

## 数据与安全保护

自动部署的运行文件位于 `data/snowluma-managed/runtime/v2.1.1-<平台>/`，下载缓存位于 `data/snowluma-managed/downloads/`。状态、授权、安装清单、账号与进程绑定都在 `data/snowluma-managed/`；这是本机私有数据，不能上传仓库。

Windows 上 Tulpa 凭据使用当前用户 DPAPI 加密。SnowLuma 必需的运行配置仍含明文 OneBot Token，存放于限制当前用户及 SYSTEM 访问的目录；这不能抵御当前用户身份下的其他程序或管理员。管理、HTTP、WS 仅监听 loopback，管理密码、HTTP Token 和 WS Token 分别随机生成，不通过命令行传递。不会更改防火墙或添加自启动。

就绪必须同时通过管理认证、HTTP 登录信息及 WS 生命周期/心跳账号核对。只收到正常元事件即可验证实时连接，不会为验收自动发 QQ 消息，也不保存聊天正文。

## 回滚与开发打包

回滚前先退出 Tulpa，确认其托管服务停止。备份整个 `data/snowluma-managed/`，然后恢复匹配的程序、安装清单和运行目录；不能单独删除凭据文件迫使上游重置。恢复独立旧实例时按本次本地备份清单恢复原路径，不覆盖测试期间新增的聊天、人格或学习数据。

开发者如需将官方运行包放入未来 Windows Release，可在现有构建命令追加 `--bundle-snowluma`。构建只复制校验通过、未初始化的原始完整压缩包及许可声明到 `resources/snowluma/`；用户运行版中的配置、日志和令牌绝不参与打包。首次勾选之前不会启动或执行这些组件。
