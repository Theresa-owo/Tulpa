# 持续聊天的本地记忆

在已授权的持续聊天中，Agent 可以自己决定保存长期有用的事实、偏好和背景：`remember_chat_memory` 写入，`search_chat_memories` 按关键词查找，`read_chat_memory` 查看全文及按页保存的原始文字依据。需要时才查询，不在每轮聊天中加载整个库；隐藏推理不写入记忆。

记忆保存在本机 `data/mcp-chat-memory.sqlite3`。它不设记录总数或自动淘汰上限，实际容量受磁盘和 SQLite 约束。单条内容最多 4000 字符，可分成多条；一次检索最多十条精简摘要，需要时再读全文。中文短语和英文关键词使用本地索引；一两个字符的短查询使用本地扫描。如果 SQLite 没有 FTS5 trigram，也会回退到本地扫描。语义近义词仍需要 Agent 换关键词查找，索引和存储不等于保证模型想起所有事实。

写入时可附最多八个当前会话已交付的事件作为依据。数据库保存顶层文字及来源元数据；如果原分段已截断，则标记为规范化内容，不冒充完整原文。引用、媒体地址或图片字节不能升级成授权。依据文字可按页查看，即使实时消息缓存随后清理；消息撤回后不能再把它作为新的写入依据。相同请求去重，修订需同时提供记忆编号和预期版本，旧版本留在本地修订表。保存失败或权限变化不会默认为成功。

记忆按连接与 QQ 会话范围隔离。相同连接、相同账号和群重新开启会话可读取已有记忆；其他群、其他连接或撤销的授权不能读取。需要跨群查询时，Agent 必须分别使用自己确实获授权的会话。记忆、群友昵称、引用、转发和模型推断均不能作为主人身份或受控工具的授权；原主人校验和 `owner_proof` 规则不变。

如果当前 Codex 任务缓存了升级前的 MCP 工具目录，服务端虽然已提供记忆工具，宿主列表可能暂时看不到。Agent 可用安装目录的 `scripts/chat_bridge.py` 按工具名调用，必要时只通过 `__schemas` 查询缺少的工具；也可重新连接 MCP 或开启新任务。桥接沿用原连接的授权，不增加权限。

`wait_chat_messages_many` 可选 `prefer_live=true` 暂缓旧积压：近期真人点名、近期主人原始消息和新话题优先；旧事件不会被确认或删除，按需关闭该选项补读。积压不妨碍在空闲时自然主动开话题，真正的新消息仍会触发重新判断。

启用省 Token 模式后，同一 `wait_state_id` 链会在已交付的回应通知没有变化时只传递增量，完整新通知、变化的通知和当前批次相关通知仍会交付。`get_chat_session(view="context")` 可按需重新读取有限历史；客户端上下文丢失后也可重新以 `session_ids` 开始等待。多群等待的 `chat_runtime` 提供当前发送门禁摘要，派发时仍由服务器重新核验。默认的完整响应保持原有结构。

这些措施减少重复传输和旧积压带来的模型调用，不能保证每个实时消息都无需模型判断。宿主若将所有工具结果无限保留在同一上下文中，单次输入仍可能增长；本功能不会暗中换模型、重启代理或宣称已触发宿主压缩。保持主动接话、图片理解和身份校验的效果，也需在真实聊天中持续观察。

本机复盘可运行 `python scripts/measure_chat_wire_replay.py <已获授权的原生会话日志路径>`；工具只输出通知条数和 JSON 字符统计，不输出聊天正文、不调用模型。结果按每群一条连续等待链模拟，不能当作真实 Token 或价格。

升级前备份整个 `data/`；Windows 保留数据升级工具会单独校验和备份此数据库及其 WAL。它包含群聊个人信息，不应提交到仓库或随安装包分享。
